### Горизонтальное партиционирование (шардирование)

Под текущую задачу на мой взгляд подходят следующие варианты шардирования: Хэшированное, Диапазонное
Т.к. в задаче нет информации о том откуда идёт поток запросов (например, с разных регионов РФ), то геоширдинг не рассматриваю
Динамическое шардинование исключаю в силу сложности реализации

Для "пилотного" запуска думаю, что лучше всего подойдет "Хэшированное" или "Диапазонное"

Релизация шардирования штатными средствами MongoDB (как раз есть реализация двух вариантов выше)
В качестве MVP реализуем:

* 1 роутер
* 1 сервис конфигурации
* 2 шарда
* Приложение при получении запроса к БД ходит напрямую к роутеру

### Репликация

Для реализации репликации используется встроенный механизм Replicaset

* 1 master узел и 2 slave

### Кэширование

* Добавляем Redis
* Если воспринимать pymongo-service как прокси ("Черный ящик") для остального приложения, т.е. приложение если хочет получить данные из БД (неважно из кэша или БД) обращается в pymongo-service, то в коде pymongo-service реализуем логику: если данных нет в кеше, то иди в роутер mongo
